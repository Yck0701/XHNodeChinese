# Codex 翻译速度优化（0.2.1）

历史两次请求从写入请求到收到响应分别约 26 秒（50 条）、46 秒（3 条），响应写入后约 2 秒导入。这些时间不区分 Codex 排队、读取文件、生成译文与工具执行，不能据此承诺固定总耗时。

- UUID 限定请求范围，条目使用请求内唯一短编号。历史 50 条样本同样格式的响应从 7406 字节减至 4297 字节，减少约 42%。
- 短词条优先；建议每批 24 个短词条或 4 段长文本，原文合计约 4500 字符。批次写完立即发布，继续完成剩余内容。
- 协议 2 支持原子写入独立 `response-0001.json`、`response-0002.json`。每个文件仍使用 request_id、translations、skipped 结构；全部批次合计每个 id 只出现一次。
- 每批完整校验占位符、请求归属和编号唯一性后导入。跨批重复编号被拒绝；重新启动会从已确认批次继续，不覆盖等待期间的个人编辑。
- `applied.json` 包含 complete、completed、total、batches。所有条目已翻译或明确跳过后才 complete=true。原先完整 `response.json` 请求仍兼容。
- 0.25 秒检测新批次，已读文件未变化时不重复解析。当前显示先更新词典，语言资源在完成或短暂空闲后合并重建，避免每批先等待全量编译。
- 状态显示等待时长、已处理数、导出准备时间、首批和总耗时。不会更换模型、另开聊天或请求其他翻译服务。

独立目标 UE 测试覆盖首次部分译文可见、余下词条仍等待、热重载续接、长文本分离、完整回执、待译清理和最终语言资源刷新。测试中的译文由脚本模拟返回，用于测量插件本地延迟；不包含真实 Codex 生成时间。具体结果见 integration-021.json。
